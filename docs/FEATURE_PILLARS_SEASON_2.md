# Feature Pillars — Season 2

## 1) Core Swap Engine
- **Purpose:** Keep the base exchange loop usable, reliable, and completion-focused.
- **Current status:** Implemented as MVP with publish → offer → accept → deal → completion → review.
- **Future direction:** Improve clarity, intention, and reduced friction across each step.
- **Example implementation:** Offer Flow 2.0 preview + Deal Room 2.0 checklist + clearer completion states.

Includes: publish, offer, redirected follow-up, accept, deal room, messages, completion, review.

## 2) Story Items
- **Purpose:** Differentiate Baddelha with context-rich items, not commodity listings only.
- **Current status:** Strategy-level direction documented; not fully productized yet.
- **Future direction:** Add story fields and story-backed presentation in publish/detail/profile flows.
- **Example implementation:** Item detail section with "item story", "why I am swapping it", "who it is good for", and condition transparency.

## 3) Trust Profiles
- **Purpose:** Make profile the trust and personality anchor of the app.
- **Current status:** Profile exists in MVP form with baseline trust loops.
- **Future direction:** Expand profile depth and readability for trust decisions.
- **Example implementation:** Profile 2.0 with cover/avatar/bio/location/interests/swap preferences/available items/completed swaps/reviews/trust badges.

## 4) Deal Rooms
- **Purpose:** Convert accepted offers into organized, lower-stress coordination.
- **Current status:** Deal pages and deal messages are implemented in MVP.
- **Future direction:** Add better structure, summaries, checklists, and safety guidance.
- **Example implementation:** Participant cards + deal summary + checklist + completion/review state model.

## 5) Creator Drops
- **Purpose:** Add premium culture layer and return-worthy discovery moments.
- **Current status:** Strategy only; no full creator system implementation yet.
- **Future direction:** Start with admin/manual curation before scaling to broader creator surfaces.
- **Example implementation:** Admin marks featured/drop item, appears with drop label and later in `/drops` page.

Includes: featured item, artist drop, creator closet, event piece, limited swap, admin/manual curation first.

## 6) Safety + Feedback Loop
- **Purpose:** Keep trust measurable and continuously improvable.
- **Current status:** Reports, ratings/reviews, and admin review are already live in MVP baseline.
- **Future direction:** Improve safety copy quality, trust interpretation, and feedback-to-action loop.
- **Example implementation:** Stronger reminders, clearer report outcomes, no public phone numbers, no sensitive image guidance.

Includes: reports, feedback, admin review, ratings, safety reminders, no public phone numbers, no sensitive images.
